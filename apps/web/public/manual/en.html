This manual is organized by feature and explains what every screen in T³ is for and how to use it. The desktop and phone share one interface; phone-specific differences are called out. For the underlying design see docs/architecture.md; for what is implemented right now see docs/status.md.

1. First run

Launching

  • Double-click T3.exe in the repo root: the desktop server starts hidden, opens your browser and lives in the system tray. Right-click the tray icon to exit.
  • T3.bat does the same thing in a console window — closing that window stops the server.
  • The first launch builds the web UI automatically; give it a moment. Later launches, when the server is already running, just re-open the browser.

Where your data lives

By default everything is under apps/server/.data/:

PathContents
library.dbThe whole library (one SQLite file)
assets/Covers, previews, thumbnails
backups/Whole-library backups
templates/Per-Gallery template files
It's just filesCopying the .data folder is a complete backup.

Opening access for your phone (optional)

Right-click the tray icon → turn on Allow phone access (LAN). This restarts the server on 0.0.0.0 and lists the machine's local addresses; click one to copy, then paste it on your phone. Turning it off returns to localhost-only.

2. Interface overview

The sidebar (navigation)

The sidebar is top-priority navigation: from any page, at any depth, clicking a sidebar item switches there immediately. It usually holds, top to bottom: Home, the search field, your Galleries (one per Entry type), Authors, Collections, View later, Recently viewed, Random pick.

On the phone (narrow screens) the sidebar becomes a slide-out drawer with an overlay, Esc, and the browser Back button.

The top bar

  • Left: a Back button (disabled on Home) and the current page title.
  • Right: the theme toggle (light/dark) and the Settings gear.

The floating buttons (lower-right)

Every view carries two fixed buttons in the lower-right corner: Back on top, scroll-to-top below. The floating Back runs the same action as the top-bar Back, so a long page can always be left.

Back remembers where you came fromOpening an Entry from an Author and going back returns to that Author, on the same page, scroll position, filter and sort. A newly opened page always starts at the top.

3. Home

Home is a "keep going" entry point, not a stats dashboard.

  • Hero: a greeting plus an Add a new entry button that goes straight to the creation page.
  • Ambient summary: rotates through "now holding N entries", "you have M galleries", "recently viewed …". It's atmosphere, not a precise stat card.
  • Recently viewed: works whose source URL you opened most recently; a card opens the Entry detail.
  • Recent galleries: a few doors back into the collection.
  • Empty state: when the library has nothing yet, it offers "add the first entry".
  • If every Gallery is hidden by your NSFW setting, Home says so and offers a Show NSFW content button.

4. Gallery

Browsing

Each Gallery corresponds to one Entry type (e.g. comic, game). Create a work with a brand-new type and that Gallery appears automatically. Works show as depth-stacked cover cards, several rows per page; the row count is adjustable in Settings.

Sorting

The Sort control next to the Gallery title offers Newest first, Oldest first, Title (A–Z), Title (Z–A), by Type, plus the rating and usage sorts below.

The filter bar

Above the grid is a filter bar of rows; everything combines with AND — every tag you add only narrows the result:

  • Facet + tags rows: type to search (near-character ranking; close spelling is accepted). A tag can be picked only once across the whole bar.
  • An All tags row matches tags regardless of Facet.
  • + Authors adds an author row; authors within that row are OR'd.
  • While filtering, the heading shows shown / total, and the Author page's Directories are temporarily unfolded into one flat grid of matches. Clearing the filter restores them.

Rating & usage sorts

Every rating dimension gets an extra sort option, Apply author rating (marked 👤): a work with no value of its own borrows its Authors' value for the same-named dimension (the highest Author value; works with four or more Authors never borrow). Rating filters still look at the work's own value only.

Usage (views / last viewed / likes) appears in sorting only — never as a numeric or date filter.

Reordering Galleries

In the sidebar, use Move Galleries to enter reorder mode and move them with the up/down buttons.

Pagination

The pager under the grid pages by the cards the layout can actually show; on phones the rows-per-page preference doubles. Changing the filter or sort returns to page 1.

Horizontal cards and image-less covers

The card layout button beside the Gallery heading switches between the vertical grid and horizontal cards. Horizontal cards show a cover on the left and a title on the right, at most two per row (one on narrow screens), with twice the configured rows per page. The choice is saved per Gallery; changing it requires a connection to the desktop, and offline copies do not store it.

In online lists, a work without a cover or preview shows its first readable Content, then its tags, then its title's first letter. Source URLs are skipped and long text is shortened to fit. Saved offline copies retain the original placeholder style.

5. Entry detail

Read mode

  • The header shows the title, a type badge, the stats row (date, pages/duration) and the toolbar.
  • The toolbar has Edit, Like (👍, re-clickable), the View later clock, 📁+ add to collection, and delete.
  • Sections and Facets lay out per the Gallery template; tags show as chips. Double-clicking a tag opens a cross-Gallery result page of every work carrying it.
  • Ratings: rated rows show a partially filled ★; unrated rows show "Unrated".
  • Content: ordered rows such as Source URL, description, or a short review. content_type is free text.
  • A view is recorded only when you open the work's source URL — opening the detail card does not count.

Edit mode (click Edit)

  • Title: double-click to edit inline; Enter or blur saves, Esc cancels.
  • Type: switching the type moves the work to another Gallery.
  • Date / pages / duration: inline. Dates accept yyyy-mm-dd, yyyy-mm or yyyy; duration accepts h:mm:ss / mm:ss / ss and can be cleared.
  • Sections & Facets: an empty Section's first row offers + Facet and + Tag together; named Facets have a label column and a tag column; Facets can be reordered. A Section's title can be renamed or deleted.
  • Tags: drag to move between Facets, double-click to rename (this work's placement only), or delete.
  • Content: add, edit, delete, reorder; Enter or blur saves.
  • Ratings: a half-star picker (0.5–5 in half steps) and a clear button per row; + Rating adds a shared dimension for the whole Gallery. The row up/down controls reorder the whole Gallery's shared slot order.
  • Authors: compact controls create / link / unlink; matching is always your explicit confirmation, never automatic.
  • Convert all Authors: appears when a work has ≥2 credited Authors and they are not all multiple author. It replaces every credited Author with one shared multiple author and does not judge who "deserves" to stay. Authors appearing only on this work fall to zero and disappear from lists (rows are kept, so a later import can relink them); Authors that keep other works simply lose this one.
  • Save as template / Apply tag layout (toolbar): the first rebuilds the type's shared layout; the second only syncs this work's tag→Facet placement onto other works of the same type (skipping tags this work lacks).
The first-time structure promptClicking Done on a Gallery's only work when that Gallery has no Sections yet raises a modal asking whether to apply this work's Sections and Facets to the whole Gallery. Applying does exactly what the toolbar's "Save as template" does.

Merging works

On an Author page, Edit mode → Merge works: pick two works of the same Gallery, then choose the keeper, the title to save, whether to union Tags, and which detected source URLs to copy. One server transaction copies and then deletes the absorbed work. The absorbed work's other Content, media, Ratings, usage, Directories, Collections and View later are not copied.

6. Creating an Entry

Reach it from Home's "Add a new entry" or the sidebar.

  • Fill in the title (required) and the type: a new name creates a Gallery, an existing name joins it.
  • Cover / Preview: pick local images. New uploads get a 512px card thumbnail automatically; the original is used on the detail page.
  • Source URL: a web URL, or a full local file path.
  • The template button (under the Gallery field): an existing Gallery reads "Template ready — open detailed editing", a new type reads "New Gallery — create its template". Either way it creates the work with what you filled in, then opens that work's own editor.
  • You can also set initial Content, initial ratings and View later membership right here.
You can create offline tooOn the phone or while offline, a new Entry (with a cover) goes into the pending queue and lands automatically when you're back online. See §13.

7. Authors

The list

  • Only Authors with at least one linked work are listed. Deleting an Author's last work hides the Author from every discoverable place without deleting the row — a later import can relink them.
  • Filter by dominant Gallery type; sort by last viewed / most viewed / most liked.
  • Two independent filter groups: Author tags (the Author's own vocabulary) and Works contain tags (tags carried by their works, not copied onto the Author). Multiple work tags must sit on the same work.
  • Cards show the Author's other recorded spellings (aliases) as a faded sub-line.

The detail page

  • One information board: basics, the Author Tags row (independent vocabulary), and the Author's content note. Authors have no Section/Facet layout.
  • Ratings: half-star picker, + Rating, shared up/down reordering. Ratings belong to the Author's dominant-Gallery partition; a workless Author shows a hint.
  • Works: Gallery-style cards, paged server-side. Opening one reuses Entry navigation; going back returns to the Author.
  • Directories: presentation-only grouping that never changes a work's type and never creates a Gallery. + Directory creates one; dropping one loose work onto another creates a Directory, dropping onto an existing one moves the work in; the Directory's title/description save inline; a work can be moved back out to "loose".
  • Author aliases (maintained under Advanced → Author aliases): one display name plus the spellings that resolve to it (kana/kanji, a translated name, romaji/English). Saving immediately merges existing duplicate rows so every spelling points at one person.

8. Collections

  • Two kinds, fixed at creation: entry collections (may have one level of subfolders) and producer (Author) collections (flat).
  • The Collections page is one flat row of pages: every Gallery, then "Unfiled" when such folders exist, then Authors. An NSFW Gallery hidden in SFW mode takes its page and its folders with it.
  • Edit mode creates, deletes and drag-reorders folders. Inside an entry collection there is + New subfolder; child folders show as folder cards above the members, and opening one does not leave Edit mode.
  • In normal mode, clicking a member opens the Entry; in Edit mode a click selects the member for organizing, then use Move here on a subfolder or Move out inside one. The remove control on a member card only unlinks it from the active folder — the work stays.
  • Adding to a Collection: Entry details and the Author board carry a 📁+ button; already-joined folders show ✓ and are disabled. The menu prefers the folders curated onto that work's own Gallery page, plus the unfiled ones.
  • Add common tag: from a folder's edit view, put one tag on every work it holds (subfolders included). Each work keeps its own Gallery's placement; Galleries with no structure are reported as skipped.

9. View later / Recently viewed / Random

View later

  • Independent Entries and Authors lists, stored in the library and shared across every desktop/phone browser connected to it.
  • Use the clock button on an Entry or Author page to add/remove; when saved it becomes a checked clock.
  • Lists keep insertion order and clients pull them on their own (no need to be online at the same time).

Recently viewed

  • Grouped by Gallery with browser-style tabs. Opens in "Last viewed" mode, hides works never viewed, shows at most 72 cards.
  • The mode buttons (★ / Most viewed / Most liked) are toggles: clicking the active one exits it.

Random pick

  • Three modes: Works / Authors / Tags. Works can be dealt from all visible Galleries, or from one Gallery narrowed by the filter bar.
  • Each press of 🎲 Random deals one page (24 work/author cards, or exactly one Tag). A Tag is revealed on a large card that opens the Tag results page.
  • Authors are filtered by their derived NSFW state; tags are deduplicated from the currently visible Galleries, so SFW mode never deals an NSFW-only tag.

10. Search

  • Focusing the sidebar search field or submitting a query opens the Search page (independent of the Gallery filter state).
  • Three scopes: Entries, Tags, Authors.
  • Close spelling is accepted; Author search also matches recorded alias spellings (the result card keeps the author's own name and shows the matched spelling underneath).
  • Tag search respects your Show NSFW preference: SFW mode omits tags used only by NSFW Galleries, and shared-tag counts include only SFW usage.
  • Navigating into a result and back carries the current query and scope, so the search state is restored.

11. Settings

Click the gear in the top bar (the daily controls live here):

  • Show NSFW galleries and authors: the global visibility switch. Off hides NSFW Galleries, NSFW Authors, NSFW members/covers/counts inside Collections, and NSFW content from Random.
  • Language: English / 简体中文.
  • Rows per page: the Gallery grid's rows per page (doubled on phones).
  • Accent color: blue / teal / violet / rose / amber / green — six presets.
  • Connect to APP: the phone-pairing block (§14).
  • Advanced function: opens the Advanced page (§12).

The top bar also has a light/dark theme toggle.

12. Advanced function

The Advanced page has several tabs; on narrow screens the tab row scrolls.

Tags (dictionary)

  • Automatically lists the library's work tags and their mappings, grouped as Unmapped / Mapped. Tags brought in by new works appear directly, ready to translate into Chinese or unify under another name.
  • Unmapped means no canonical name has been assigned. Fill in a mapping or keep the original name; author names are managed under Author aliases.
  • Delete tag requires a second confirmation and removes the tag from every linked work. Removing a mapping deletes only that mapping; these actions have separate controls.
  • Tag merge: pick the tag to keep and the tags to absorb; after confirming, all assignments re-point to the kept tag and the merged rows are deleted (with a pre-transaction backup).

Author merge

  • One-button duplicate detection: the first tap only plans the groups, the second executes (with backup + integrity report).
  • Detection rules: identical normalized names; separator variants (_/-/. count as whitespace, so arai_kazuki and Arai Kazuki are one Author); and spellings that resolve through the producer dictionary to the same canonical name.
  • Each group keeps the row with the most works; on equal work counts the separator-free spelling becomes the display name. Works, Author tags, Author ratings and Directories transfer to the survivor.

Author aliases

See §7, "Authors".

Gallery templates

  • Per-Gallery summary: structure dimensions, tag→Facet assignments, the local file paths (<type>.template.json / <type>.tag-layout.json) and whether they exist.
  • Saving/applying a template happens on any Entry card (the toolbar's "Save as template" / "Apply tag layout").
  • Common template: the repository's built-in Sections/Facets (basic info / Type / Characters / Language / Tags / All tags / overall rating). Applying copies them into that Gallery, where they can be renamed, emptied or deleted like any template you built. It also brings the "Content kinds" note (each Gallery has built-in Source URL / description; a work shows a row only when it has text).
  • Title shortening (a sub-card inside the Templates card): for Entries titled original | translation, it lists both sides and lets you pick which to keep. It pre-selects by determinable direction (the translated side when it carries Han/Kana; the original when the other side is only Hangul; nothing when both sides are ASCII). It writes a database backup first and only applies entries whose title still matches the plan.

Unassigned tags

  • Lists, per Gallery, tags still sitting in the unnamed default position; pick a target Facet to move them (entries that already classify the tag are skipped).
  • When a majority of same-type entries keep the tag in a named Facet, a Follow button moves them there in one click.

Source maintenance

See §12, "Source library".

System

  • Errors and log: shows the desktop server's log tail and recent client errors, with Copy for a bug report.
  • Phone pairing diagnostics: shows this app's local scan, connection, authorization verification, and storage stages. A pairing-failure dialog can copy the report directly, even before pairing or when the desktop is unreachable. An installed older app only provides diagnostics supported by that version.
  • Database: Back up now, Export (downloads as a real library file), Restore from file. A restore is staged: the upload is validated and kept aside, and you must exit the desktop from the tray and open it again to put it in place (the replaced library is backed up first).
  • Settings: Automatically allow phone access at startup (on by default). Turning it off keeps the desktop invisible to the network.

13. Importing from websites

Import has two doors, both inside T³: the rule builder (learn a site) and link import (commit a crawl's output).

Step 1 — the rule builder (SiteProbe)

It opens a real page in your browser, lets you click the parts you care about, and learns that site's rules. It is guided start to finish; the first adapter takes a few minutes of your attention.

  1. Prepare 2–3 work addresses of the site (work adapter). Favour pages that actually carry what you want — many tags if you want every tag, several authors if a work can have them.
  2. Click "start the work-page adapter"; the builder opens the annotation page. Copy a real value from the page, paste it into the search box, and pick the closest match. The tool scores candidates, but the score is not the point — pick the best match. Values like $authorS$ or 123title456 look like page code and can score high, but if the clean value is shown on the page the tool has also harvested it.
  3. One / Several: author, tag, character, and other multi-value fields offer a mode switch. In Several mode, click members to add or remove them, or select one whole tag block to see its split members. If a derived rule reads additional members, the save message lists them; they will also be imported.
  4. Long descriptions and later corrections: long values are abbreviated on screen with their full character count; saving and importing retain the full text. A value already truncated by the website has a separate warning. A later selection takes priority for that field; fields you did not change keep their earlier choices.
  5. When it says the adapter is built, you can import the first work for preview.
  6. Optionally add a listing adapter (search / artist / favorites / album / playlist): give the listing's first and second page URLs (the second is required — it teaches pagination), then annotate the cards.
Browser acquisitionThe tool can use system Edge / Chrome or bundled Chromium / Firefox. Complete sign-in or security checks manually in the browser, then continue the task. Site-specific encryption, private interfaces, or complex restrictions may still need dedicated adapter rules.
A rule must name its own addressesA learned listing must be able to turn the page and locate each card's work address — a rule that knows only one address is a failed design. That is why the second page URL is required.

Step 2 — link import

Reopening the panel recovers running imports, sign-ins, and rule-building jobs, with a stop control. A builder waiting for annotation can run alongside an import using an installed adapter. If another export holds the shared output directory, the panel identifies that job and its log. Pasting a new address retains access to the running job's controls.

  1. The creation page (and the Advanced import panel) offers Import an export folder (drop or browse) and Batch import (drop a parent folder containing items/<id> subfolders).
  2. Choose the Gallery / type. The mapping is prefilled from that type's saved template: 分类标签→tags, 作品→Series, 登场人物→Characters, 作品类型→Type, language→Language, 作者→Author. Unmapped fields stay explicitly "Ignore" — nothing is guessed.
  3. If the Gallery has no template yet, T³ offers to take the common template or to build your own (otherwise the works' tags would be lost).
  4. A template preview card shows live where each mapped field will land. When the template owns a Type Facet you can type a work type (saved as a Tag under that Facet) for sites whose exports omit it.
  5. Per-author ratings: the review does not rate individual works; it offers a rating per Author name — tick "Rate this Author" to reveal the Gallery's rating dimensions. The rating is stored on the Author and shared by the whole batch.
  6. Click "Import N Entries". Import is idempotent: works already present are skipped and reported as "Already in the library", so importing the same batch twice is safe.
The post-import reviewAfter importing you land in a one-time batch review listing the new cards and the "already in the library" ones. Finish it or leave from any sidebar item. If a batch is too large to check in one sitting, click Save as temporary Collection to file the whole run into a Collection named 临时 / 临时2 / …, which survives the review.

Updates and cursors

The library remembers each site's work IDs and each listing's update cursor. Re-crawl the same favourites folder a month later and only the new works need fetching. Command-line entry points:

pnpm import:cursor status --site hitomi.la --kind folder --ref folder-42
pnpm import:cursor filter --site hitomi.la --ids 100,120   # ids not held yet
pnpm import:cursor set    --site hitomi.la --kind artist --ref some-artist --source-id 3220586 --commit

Source library & Source maintenance

  • The Source library is derived dynamically from every work's Content: known sites are grouped as known:<site>, others as host:<hostname>. Content you add by hand is recognized immediately with no extra sync.
  • Source maintenance handles a site going invalid or changing domain: annotate a source group as invalid (annotation only — no Content is touched), run a search job whose candidates are banded by evidence (exact-safe / strong-review / …), review, then commit once. The commit re-verifies every item and takes a real backup; any stale fact aborts the whole batch (409, zero writes). Old URLs are never replaced or deleted — new Source URLs are appended.

14. Offline library

The browser (including the phone app's WebView) can keep an offline copy: browse and make some edits without a connection, then sync automatically when you're back. Its settings are under Advanced → Offline library.

First download

  1. Click Download offline library. Choose an offline-media level: Metadata only (no images), Thumbnails (no originals), or Selected originals (list the asset refs).
  2. The download installs metadata first, then prefetches media; progress shows processed/total. Preload runs only while the page is open; interrupted downloads resume on the next launch.

Automatic update & sync

  • On reconnect, local edits are replayed automatically (syncing), then the saved copy is updated automatically (updating) — there is no manual "Sync now".
  • Idle heartbeats never re-download; a failed update stays due for a later heartbeat.
  • Progress and error banners are informational and disappear on success.

What works offline

  • Browsing: Galleries, Entries, Authors, filters, Collections, Search, Random, View later and the other reads.
  • Editing existing works: title / date / pages and other scalars, rating values, tag add/move/remove, Author create-and-link/unlink, Content add/edit/remove/reorder, and an Entry's cover & previews (add / replace / delete / order).
  • Creating: a new Entry with a cover/preview.
  • Collections: create, rename, NSFW, membership, ordering.
  • Usage events: views and likes (each is an independent event, so a lost response never double-counts).
Not offlineDeleting an Entry, merging works, importing, and template/dictionary (global) operations still need the desktop server. The UI marks these not available under offline rather than attempting a doomed request.

System information & diagnostics

The bottom of the Offline library page holds diagnostics: an Offline editing support summary, storage usage and persistence status (checked and requested automatically), and a copyable full report (cached capability flags, snapshot header and ACK, local intentions, media/outbox errors, native-transfer status). Paste that report when reporting a problem.

Pending work

Pending work (queued edits and staged images) is transparent: it syncs automatically on reconnect, and there is no manual export/restore control in the UI.

Cleanup only after landingA queued operation is removed locally only once it is proven applied on the server (a newer snapshot covering its receipt). Cancelling a queued operation never quietly destroys data.

15. The phone app

Pairing (once)

  1. On the desktop, open Settings → Connect to APP and click Create pairing QR.
  2. The QR is valid for 2 minutes — scan it right away; a copy/paste fallback is also available (not a camera scan).
  3. The connection is encrypted and certificate-pinned. Certificate or authorization failures never clear queued work.

The panel also lists Authorized devices (revoke a device or remove a record) and has a collapsed manual encrypted connection recovery section for a crash-left dead lock; it asks you to verify the real PID — never a guess.

The current app's pairing failures identify stages such as QR expiry, connection or certificate validation, authorization, and storage, and show a diagnostic ID. Copy the local report before following the specific instructions; the desktop log can be correlated with the same ID. Reports omit QR contents, authorization tokens, and pairing keys.

Using it

  • The phone is the same interface, responsive; on narrow screens the sidebar becomes a drawer.
  • Every touch interaction has a clear tap path (never hover-, long-press- or HTML5-drag-only); touch targets are about 44×44 CSS px.
  • Destructive actions use the same two-step arm/confirm pattern as the desktop.
  • Browser Back and the in-page Back both restore the source page and scroll position; a new page starts at the top.

Offline & sync

The phone keeps an offline copy: browse, edit, create, add images and merge (some) with no connection, then it replays and updates automatically. Android schedules network-constrained background work; edits that depend on an unfinished predecessor wait for it. Very large images (native limit 20 MiB) need a foreground Update.

Anything beyond the offline allowlist is marked inside the app as not available under offline instead of trying to reach the server and reporting its error.

16. Backup & restore

  • Command line: pnpm db:backup writes a self-contained backup directory (library snapshot + assets/ + manifest); pnpm db:restore <backupDir> restores. A restore first checks the backup passes db:doctor and snapshots the current library.
  • In the app: Advanced → System → Back up / Export / Restore. A restore is staged and needs an exit-and-reopen from the tray.
  • Stop the T³ server before restoring (otherwise it fails with a clear "file in use" error rather than a silent partial overwrite).
  • Only complete backup directories are restorable through the tool; legacy single-file snapshots (library.db.merge-backup-*) lack the assets tree.

17. Troubleshooting

"Viewing the saved offline copy"

The desktop server can't be reached right now, so the offline copy is in use. It switches back and syncs automatically once the server answers. A few seconds right after a desktop restart is normal.

I changed server code but the UI didn't

The packaged entries (T3.exe / T3.bat) load the server sources once at start and need a restart; rebuilding only the web UI leaves a fresh front-end talking to an older server. In development use pnpm dev:server (with watch).

Phone: typing shows no suggestions

The known IME (composition) bug is fixed: the field reads input through a plain @input handler (v-model drops events while composing). If it still misbehaves, make sure you're on the latest build.

A cover in the grid looks stale

Media addresses are positional, so the same address can hold different bytes over time. After changing a cover, reopen the work; the detail page always reads the original.

Import says the server may still be working

The import didn't finish in the expected time, but the server may still be writing. Importing the same batch twice is safe (it's idempotent) — check the works list before retrying.

Reporting a bug

Go to Advanced → System or the bottom of Offline library and click Copy for a bug report. Paste the whole report to the maintainer; it includes the log tail, recent client errors, capability flags and queue state.

# T3 1.0 发布前遗漏检查

日期：2026-10-12。基线：当前工作树；Android 最近交付 r25。

本轮只读核对需求记录、现状文档、页面入口、运行依赖、发布配置和现有验收证据。没有修改应用代码、运行全套测试、读取正式数据库或重新安装应用。下文“已实现”不等于本轮重新逐项实机验收。

排除浏览器插件、未来归档分享、规模达到门槛后的搜索/图片架构升级，以及用户本轮明确暂不处理的原生持久存储保障。

## 结论

当前主要业务模块已存在，没有发现需要在 1.0 前再开发一个新的大型业务模块。发现一个未落地、未明确延期的旧需求；更大的缺口是面向普通用户的发布、安装、更新、说明和版本验收，当前仓库仍以开发工作区运行。剪贴板自动识别也未实现，但旧实施方案已列入“明确不做 / 留给以后”，按本轮范围排除。

## 3. 已有功能的边界和验收欠账

### 备份不是完整资料库搬迁包

系统页已有数据库备份、下载和暂存恢复；`system-routes.ts:140` 调用 `database.backup()`，不是未实现备份。它只输出数据库文件，不包含 assets 图片、SiteProbe 用户规则、设置及配对授权。因此“数据库恢复”不能宣传成“换台电脑恢复全部资料”。原始需求明确写的是数据库，此处不强制扩展为新备份模块；1.0 至少需要写明边界，并在更新/搬迁说明中处理这些文件。

### 当前版本验收范围仍不完整

r25 已有真实手机队列 12 → 0、自动重连更新、横幅消失、诊断复制和同签名覆盖安装证据。但没有覆盖所有普通编辑组合、Android force-stop/重启/后台生命周期和普通用户干净电脑安装。`v49-device-acceptance-checklist.md` 多数 B 项没有记录，旧 `offline-validation-checklist.md` 仍引用 v40。空白记录不证明用户没测过，只表示不能从仓库宣称 1.0 全量验收已完成。

这轮没有重跑全套门禁；不能把以前 r19 的整树测试通过直接当成当前修改树的发布证明。应冻结明确版本，再完成有限的发布验收：干净安装、已有库升级与保留数据、手机配对、离线连续编辑/重连、数据库备份/恢复。

### SiteProbe 的当前收尾

2026-10-11 稳定化方案的 B–F 已有源码、聚焦测试和录制回放证据，不能因文件开头“待执行”就列为整模块未完成。该文档末尾仍留有真实站点/UI 验收、旧规则 metadata/doctor 提示，以及 probe/doctor 更完整地进入 T3 作业/界面的待办。源码中 job 对 probe 事件仍直接忽略；当前失败 findings 面板已经存在。

这不是要在 1.0 承诺“所有网站可自动适配”。应确认正式包中的 Python/浏览器依赖和内置示例，验收单网址、列表、review → selection → 导入已有闭环；把实站兼容范围写明。私有 `.data/siteprobe` 里的规则不能直接变成公共发行内容。

## 4. 未发现需要重新开发的主模块

现状文档与对应组件/路由已有 Entry/Producer、Gallery/Section/Facet/标签、Collections/Directory、搜索/筛选/分页、作品与作者评分、作品摘要评分回退、使用记录/View later/Recent/Random、封面与预览/缩略图、模板、批量导入/去重/游标、SiteProbe/Builder/登录与手动 review、Source maintenance、系统诊断/数据库备份恢复、手机配对/TLS、离线本地最终结果与自动同步，以及中英文 UI。

这份清单是实现覆盖判断，不是每个按钮或每个站点重新运行通过的证明。

## 5. 建议完成顺序

1. 明确 Source 本地路径打开是否进入 1.0，避免口头遗漏。
2. 完成发布脚本、运行依赖、正式版本/签名以及更新/卸载的数据保留规则。
3. 完成发布包白名单、README/手册、备份边界说明和许可证材料。
4. 冻结同一源码版本，在干净电脑和手机完成有限的 1.0 发布验收，再发布。

没有把浏览器插件、已延期的剪贴板自动识别（`b-advanced-import-plan.md:142–150`）、未来 save-share、原生持久存储增强、FTS/图片规模优化等列入这份 1.0 欠账。

## 状态快照（2026-09-11）

- 当前范围内的桌面端、手机端、LAN、导入、搜索、评分、使用记录、合集、
  View later、随机推荐、作者词典与别名、服务端分页及缩略图任务均已完成并验收。
- Gallery、Author、Search、Tag、Recently viewed、Random、View later、Home、
  Author works/directories 与 Collection members 均使用有界服务端查询；Web
  主路径不再依赖完整 Entry/Producer 数组。
- Author Edit 下提供独立作品合并模式：选择同作者、同 Gallery 的两个 Entry，
  选择保留标题，可合并 Tag，并把另一 Entry 的 Source URL 复制为新 Content；
  服务端在单一事务中完成校验、迁移和删除。
- 小任务与改动第 1 项已完成：Author 列表、查询与搜索只返回当前至少关联一个
  Entry 的 Producer。删除某作者的最后一件作品只会隐藏该作者，Producer 行不删除，
  后续导入可以重新关联；直接详情访问仍可用于创建/编辑流程。
- 小任务与改动第 2 项已完成：18comic 与 Hanime 提取时都会生成/更新项目级
  `taxonomy_dictionary.json`（`series`/`authors`/`characters`/`types`/`tags`
  五区）与只留 pending 的 `tag_review.csv`；繁→简由 OpenCC `t2s` 在本地确定性
  转换，不使用 LLM 或翻译 API。源站字样始终保留为字典键，已有非空人工译名一律
  不覆盖，只有空值和待审核行由自动转换预填。已用 inventory-only 方式为现有导出
  补齐字典，导出 metadata 指纹前后一致。
- 导入时若同一件作品把同名标签同时放进两个 Facet（例如一个多作品合集把 Goblin Slayer 同时
  列为作品与登场人物），导入不再整体失败：保留第一个位置（作品自身标签优先，其次按映射字段
  顺序；已有既定位置的标签两边都走同一 Facet），并在批量导入的临时合集页把被跳过的位置列为
  提示（`importCommitResultSchema.warnings`）。
- 作者页的作品列表每页数量改为按实际布局计算（6/3/2 列 × 每页行数偏好，手机端翻倍），
  不再写死 26；此前第一页会只填 4 行加 2 个卡片就翻页，现在正好填满一屏（桌面 6×5）。
- 作者合并现在也会迁移 `producer_rating_values`（作者评分），因此合并不会再丢失评分、也不会
  留下指向已删除作者的外键悬空行；早先版本遗留的悬空评分行会在下一次合并时自动清理，合并后的
  完整性检查（`foreign_key_check` + doctor）恢复通过。
- 临时合集复核页的页码不再跨批次复用（每次批次有独立 page-key），且共享卡片网格的本地分页
  切片按当前页数钳制，越界页码不会再渲染成空白；复核加载失败也会显示错误而不是静默变成空列表。
- 导入时若作品署名的作者是已记录的别名拼写，会**链接到**该别名指向的既有作者（文档一直
  承诺的行为），不再新建同名重复行：例如署名 `冷泉` 的作品落到既有的 `和泉`，无论复核页是否
  预选了该匹配；只有库中确实没有该 canonical 作者时才新建。
- Search 页的作者搜索也会匹配该作者已记录的别名拼写（如输入 `ishikei` 能找到 `石恵`），
  结果卡片仍显示作者本名，并在下方以淡色显示命中的那个拼写；canonical 仍为空的占位别名不参与
  匹配。范围仅限搜索（`queryProducerPage` 的 searchQuery 路径）。
- Source library 从所有 Entry Content 动态提取 HTTP(S) URL；已知网站使用稳定
  source key，未知网站按标准化 hostname 分类。手动新增或修改 Content 无需额外
  同步即可被识别。
- 导入评分按作者记录：导入复核页不再给整批作品打统一分（单件导入的作品评分块也一并
  移除），改为按作者名提供评分，勾选"给该作者评分"后才展开该 Gallery 的评分维度；
  评分写在导入的同一事务内，重复导入只会 upsert，作者评分维度按其所属分区按名字镜像
  自 Entry 维度。批量导入选好文件夹后会先预览第一件作品，以便在运行前确认作者与评分；
  批量对话框打开时复核区只显示提示，不再出现单件提交按钮。
- 筛选栏"按评分排序"每个维度多出一条"应用作者评分"（标签用 👤 符号，避免 native select
  按最长选项撑宽筛选栏；该下拉同时有 11rem 宽度上限）：作品自身评分优先，缺失时回退到
  该作者在同一维度上的评分（取作者中的最高分），关联作者数 ≥4 的作品不回退。评分
  **过滤**仍只看作品自身评分；该模式不占用新的筛选槽位。
- 小任务与改动第 3 项已完成并按要求修订：Entry 编辑模式新增一键"全部转为多作者"。
  它把该作品的**所有署名作者**都替换为一个共享的普通作者 `multiple author`（已存在
  则复用），不再判断谁"值得保留"——有其它作品的作者只是不再关联本作品，因此完全只出现
  在多作者作品里的作者会归零并从所有列表消失；被清空的作者行不删除，后续导入仍可重新
  关联。界面只在"至少两位署名作者且其中不只是 `multiple author`"时显示该按钮；少于
  两位作者时服务端返回 409 且不写入。真实数据副本演练：可见作者由 121 降至 40，
  "名下全是多作者作品"的作者由 82 降至 0。
- migration 013 已应用于正式数据库；作品合并和 Source library 不需要新 migration。
- Advanced editing 新增「标题缩减」：针对 `原文 | 译文` 形式的标题，逐条列出两侧，由你决定
  保留前半还是后半（默认按可判断的方向预选：另一侧是中文/日文时保留译文侧；另一侧只有韩文时
  保留原文侧，因为韩语标题不能替代原文；两侧都是纯 ASCII 时无法判断方向，不预选、保持原样），
  只有你选中的条目才会执行。生成清单 → 逐条选择 → 二次确认后执行，执行前自动备份数据库，
  且只应用标题仍与清单一致（未在此期间被改名）的条目。真实数据：719 个作品中 112 条候选，
  可预选 97 条（平均长度 56 → 15 字符），15 条需人工判断；不含 `|` 的标题不在处理范围内。
- 作者合并检测（Settings → Advanced editing → Author merge）新增"分隔符变体"规则：
  `_`、`-`、`.` 视为空白，因此 `arai_kazuki` 与 `Arai Kazuki` 会被识别为同一作者；
  作品数相同时优先保留不含分隔符的拼写作为显示名，作品数多的拼写仍然优先。该键只用于
  合并检测，`normalizeTag` 本身不变（标签去重、导入字段键、词典解析行为不受影响），
  导入时的作者匹配也仍然完全由用户确认。
- cover/preview 上传会生成 512px WebP 卡片缩略图；原图仍用于 Entry 详情。
- 手机端 Gallery/Author 跨页进入详情后，顶部 Back 会恢复原页和滚动位置。
- 正式入口仍为仓库根目录 `T3.exe`；`T3.bat` 仅作备用。
- 站点提取工具位于 `D:\Project\Dataextracted\site_probe\`（不在本仓库内），
  其 `exports/` 为私有数据且被多站点 `.gitignore` 排除。
- 默认单元测试（234）、集成测试（215）、typecheck、lint、production build 与
  `db:probe`（含 doctor 洁净）均通过。测试必须使用启动器选定的项目本地 Node
  （当前为 Hermes Node 22）；Node 26 自带全局 `localStorage`，会让 jsdom 用例
  大面积误报，详见 `docs/current-architecture.md`。
- 修复了上一轮中断遗留的两个测试层问题：`gallery-app.test.ts` 中对 `get()`
  结果调用 `exists()` 导致的 typecheck 失败；以及该文件每个 `mount` 未卸载、
  window focus/popstate/keydown 监听持续累积，使末尾依赖焦点事件的用例耗时
  约 10 秒并触及超时（现已启用 auto-unmount，该用例降至毫秒级）。

- 批量导入后的临时复核界面新增「存为临时合集」：一键把本次导入的全部条目放入一个新合集，
  命名为 `临时`、`临时2`、`临时3`…（服务端取第一个未占用的名字，同一事务内创建并加入成员，
  已不存在的条目跳过而不整体失败）。复核是一次性的，合集会在复核结束后保留，用于像 18comic
  收藏夹这种一次录完、一时复核不完的分批检查。
